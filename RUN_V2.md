# Seminar version 2

The user authorized these changes and a fresh seven-agent run on October 8, 2026. This is a new experiment with the same population and a new hidden $10 allowance per agent; it does not continue or rewrite the prior incomplete experiment. The prior run and its charges/reservations remain preserved.

Every active participant must contribute an opening board post or reply before drafting begins. All agents receive identical prompts and retain numbered identities only. There is no total turn or session-time limit, and agent environments have no network access.

Malformed/no-tool/provider-error responses receive at most two additional generation attempts in each consecutive failure chain, with an identical neutral action-format reminder. Raw responses and controller interventions are recorded. Tool effects are never replayed. Unrecoverable participants are explicitly technically excluded from the final signing quorum, without consent or fabricated dissent. Ordinary interruptions remain unresolved. Budget withdrawals remain separately attributed to the controller.

Missing/invalid usage metadata first triggers up to three read-only lookups of the existing OpenRouter generation's metadata. This never repeats generation. If reconciliation fails, its full conservative reservation remains deducted and only the affected participant is quarantined. Persistence failures and unsafe accounting still halt dispatch. Read-only billing lookup documentation: https://openrouter.ai/docs/api/api-reference/generations/get-request-&-usage-metadata-for-a-generation

Wait results batch new message bodies and meaningful state changes. Older unread threads do not repeatedly wake the model; they remain available through board tools. An all-waiting condition wakes participants once per activity generation. Approvals remain in a durable historical record even when an edit invalidates them or a controller interruption occurs.

The dashboard distinguishes technical exclusions, voluntary exits, controller budget withdrawals, current approvals, and historical approvals. A submitted constitution describes agreement only by its remaining signing quorum, not the original seven if anyone was excluded.

Offline verification covers the real gateway admission and reconciliation paths with mocked upstream responses, malformed recovery, exclusion and opening-review rules, journaling/reload, final signatures, container command constraints, and dashboard JavaScript rendering. These tests do not establish actual provider reliability or quality of deliberation.
